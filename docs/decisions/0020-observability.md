# 0020. 관측: Prometheus+Grafana 자체 호스팅 + 공개 서브도메인

- 상태: Accepted
- 날짜: 2026-08-21
- 관련: 0019(배포 인프라 — VM+매직 도메인)

## 맥락 (Context)
배포 6단계 중 4번(관측). `01_기술_로드맵.md`가 처음부터 예정해둔 항목이고, ADR 0019도
"로드맵의 관측·부하테스트·상시 워커와 자연스럽게 맞물린다"는 걸 VM 직접 운영 선택의
근거로 이미 인용했다. 두 가지를 정해야 했다.
1. Prometheus·Grafana를 어디서 운영할지 — 이미 RAM 1GB(t3.micro)에 api/web/redis/Nginx가
   떠 있는 VM에 더 얹을지, 관리형 무료 서비스(Grafana Cloud)를 쓸지.
2. Grafana 대시보드를 어떻게 볼지 — 서브도메인으로 공개 노출할지, SSH 터널로만 접근할지.

## 결정 (Decision)
- **VM에 직접 호스팅**한다. `node-exporter`(호스트 CPU/메모리)·`prometheus`(수집·저장,
  15초 주기·7일 보존)·`grafana`(시각화) 3개 컨테이너를 `docker-compose.prod.yml`에 추가.
- **Grafana는 `grafana.<IP>.sslip.io` 서브도메인으로 공개 노출**한다(Nginx+Let's
  Encrypt, app./api.와 동일 패턴). Grafana 자체 로그인(admin 계정, 강한 비밀번호)으로 보호.
- `apps/api`에 `/metrics` 엔드포인트를 신규 노출한다(전역 게이트 가드는 `@Public()`으로
  우회 — Prometheus는 데모 토큰을 안 가져오고, Docker 내부 네트워크로만 접근하므로 안전).
  요청 수·응답시간 히스토그램(p95 계산용)·confirm/payment 큐 적체(waiting/active)를 직접
  계측. process/node 기본 지표는 라이브러리 기본값 그대로 함께 노출.

## 고려한 대안 (Alternatives)
| 대안 | 장점 | 단점 / 채택하지 않은 이유 |
|---|---|---|
| **Grafana Cloud 무료 티어** | VM 리소스 전혀 안 씀, 기존 서비스 안정성에 영향 없음 | "인프라 직접 운영" 학습 취지(ADR 0019)와 어긋남 — Prometheus 구성·Grafana 프로비저닝을 직접 안 해보게 됨. |
| **VM 호스팅 + Grafana Cloud 병행** | 리소스 절약하면서도 Prometheus는 직접 운영 | 굳이 두 시스템을 나눌 이유가 없음(복잡도만 늘고 배우는 것도 안 늘어남). |
| **Grafana SSH 터널 전용** | 공격 표면 추가 없음 | 볼 때마다 터널을 열어야 해 포트폴리오 시연 편의성이 떨어짐. |
| **VM 직접 호스팅 + 서브도메인 공개 (채택)** | 학습 가치 최대(설치·설정·트러블슈팅 전부 직접), 포트폴리오로 바로 시연 가능 | RAM 1GB 박스에 컨테이너 3개를 더 얹는 리소스 리스크 — 완화책(스왑 1GB, mem_limit, 7일 보존)으로 대응. Grafana 공개는 공격 표면 추가지만 Grafana 자체 로그인으로 방어. |

## 근거 (Rationale)
§0 "학습 최우선" 원칙과 ADR 0019가 이미 확정한 방향의 연장선이다. 매니지드 서비스는
편하지만 이 프로젝트의 목적(백엔드·인프라 학습)과 어긋난다. 서브도메인 공개는 이미
app./api.에도 같은 패턴(무료 매직 도메인+Let's Encrypt+Nginx 리버스 프록시)을 쓰고
있어 세 번째를 추가하는 데 새로운 개념이 필요 없었다.

## 결과 (Consequences) — 실제 배포 중 확인된 것 (2026-08-21)
- **RAM 리스크가 실측으로 확인됨**: 배포 직전 VM 여유 메모리 376MiB(전체 908MiB)였는데,
  Grafana 최초 부팅만으로 설정한 상한(200m)의 99.95%를 즉시 소진 — 안 고쳤으면 실사용
  중 OOM이 확실했다. **300m으로 상향(실측 후 조정, 부팅 직후 168.8MiB, 56% 사용)**.
  Grafana OSS의 부팅 베이스라인이 생각보다 높다는 걸 문서화해둔다 — 다음에 비슷한 걸
  올릴 때 "일단 작게 잡고 스크레치"보다 여유 있게 잡고 실측 축소가 더 안전할 수 있다.
- **스왑 1GB를 VM에 신규 추가**(`/swapfile`, `/etc/fstab`에 등록해 재부팅 후에도 유지) —
  메모리가 부족해질 때 완전히 죽는 대신 느려지는 정도로 버티게 하는 안전망. 이 프로젝트
  이전엔 스왑이 0이었다.
- `/metrics`는 Prometheus가 Docker 내부 네트워크(`api:3001`)로만 접근하고 Nginx가 이
  경로를 라우팅하지 않으므로 공인 인터넷에는 노출되지 않는다 — `@Public()`으로 게이트를
  우회해도 안전한 이유.
- 다음 세션(또는 이어서): 실제 Grafana 대시보드 패널(요청률/p95/에러율/큐 적체) 구성.
