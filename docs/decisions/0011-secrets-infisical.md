# 0011. 비밀값 관리: Infisical (시크릿 매니저)

- 상태: Superseded(2026-08-21 — 배포 시점 재검토 완료, "로컬 `.env` 수동 관리"로 정식 확정. 2026-08-08엔 잠정 관찰이었음)
- 날짜: 2026-07-14
- 관련: 0010(Neon — 두 기기 공유)

> **개정 이력 (2026-08-08 — 배포 전 ADR 점검 중 발견한 드리프트)**
> **솔직한 인정**: 이 ADR이 결정한 `infisical run -- <명령>` 런타임 주입 방식은 W1~W2 초반 이후로 실제로 쓰이지 않고 있다. 이 기기엔 `infisical` CLI 자체가 설치돼 있지 않고(`which infisical` → not found), `apps/api/.env`가 평문으로 존재하며 이 세션 전체(인증·데모·대기열·결제·프론트엔드)가 그 평문 `.env`만으로 진행됐다. `docs/DEVLOG.md`의 W2 시점 기록에 이미 "서버는 infisical 없이 `pnpm start:dev`"라고 적혀 있고, 그 이후 어떤 세션 기록에도 `infisical` 사용 흔적이 없다.
>
> **즉 실제로 벌어진 일**: 이 ADR이 "채택하지 않은 이유"로 명시적으로 기각했던 대안 — **"로컬 `.env` 수동 공유"** — 가 사실상 지금까지의 기본 운영 방식이 됐다. 원안이 우려한 위험("유출 위험·기기 간 수동 동기화 실수")은 감수된 상태로 남아있다(두 기기 간 `.env` 값을 그때그때 손으로 맞춰온 것으로 추정 — `docs/STATUS.md`의 "이 기기 로컬 환경" 섹션이 매 기기마다 값을 다시 적어두는 방식이 이걸 뒷받침한다).
>
> **왜 지금 바로 고치지 않고 기록만 남기는가**: 이 프로젝트는 배포된 공개 데모의 비밀값(`DEMO_GATE_PASSWORD` 등)이 애초에 "비밀 유지"가 목적이 아니라(ADR 0016 참고 — 크롤러 차단용) 유출돼도 실질 피해가 크지 않고, `JWT_SECRET`·`GOOGLE_CLIENT_SECRET`·`DATABASE_URL` 같은 진짜 민감한 값도 로컬 개발 단계에서만 쓰이고 있어(운영 배포는 아직 미착수, STATUS.md "다음 할 일" 참고) 급하게 막을 실질적 위험이 지금은 없다고 판단했다. 다만 **배포 시점(§배포 6조각의 VM 배포 단계)엔 이 문제를 반드시 재검토해야 한다** — 그때는 실제 공개 서버의 진짜 비밀값이 걸리므로, Infisical을 다시 도입하거나(원안 유지) 이 ADR을 "로컬 `.env` 수동 관리"로 정식 Superseded 처리하거나 둘 중 하나를 그때 확정한다.

## 맥락 (Context)
두 기기에서 비밀값(DB 연결 문자열, JWT 시크릿, Redis URL 등)을 공유해야 한다(ADR 0010). `.env` 파일을 슬랙·USB로 수동으로 나르는 방식은 유출 위험이 크고, 동기화 실수가 잦다.

## 결정 (Decision)
시크릿 매니저 **Infisical**(무료·오픈소스)에 비밀값을 저장하고, 실행 시 `infisical run -- <명령>`으로 **런타임에 주입**한다. 디스크에 평문 `.env`를 두지 않는 것을 지향한다.

## 고려한 대안 (Alternatives)
| 대안 | 장점 | 단점 / 채택하지 않은 이유 |
|---|---|---|
| **로컬 `.env` 수동 공유** | 도구 불필요 | 유출 위험·기기 간 수동 동기화 실수. 이번 요구(안전한 공유) 불충족. |
| **Doppler** | 개인 무료, 셋업 가장 빠름 | 클로즈드 소스. 학습 투명성은 Infisical이 우위. |
| **1Password** | 이미 쓰면 편리, `op://` 참조는 커밋 가능 | 무료 단독 플랜 없음(유료 $7.99/월~). |
| **Infisical (채택)** | 무료 티어(3프로젝트/5아이덴티티), 오픈소스(자체호스팅 가능), CLI 주입, 원리가 투명해 학습에 좋음 | 유료 전환 시 identity 기반 과금, 약간의 러닝커브. |

## 근거 (Rationale)
무료 + 오픈소스 + 원리 투명이라 학습 프로젝트에 최적. `infisical run` 주입 방식은 `.env` 파일 자체를 없애 유출면(공격 표면)을 줄인다. 집 노트북에선 `infisical login`만 하면 동일 비밀값을 즉시 사용 → ADR 0010의 "두 기기 공유"를 안전하게 완성한다.

## 결과 (Consequences)
- 실행 형태가 바뀐다: `infisical run -- npm run start:dev`, `infisical run -- npx prisma migrate dev`.
- `apps/api/.env.example`은 **"필요한 키 목록·형식" 문서**로 유지한다(실제 값은 Infisical에 저장).
- 로컬 `.env`는 여전히 gitignore. 급할 땐 로컬 `.env`로도 실행 가능하지만, 공유가 필요한 비밀값은 Infisical을 단일 소스로 둔다.

## 개정 이력

- **2026-08-21 (배포 시점 재검토 완료, 최종 확정)**: 위 2026-08-08 개정 이력이 예고한 "배포 시점 재검토"가 실제 VM 배포(2026-08-19~21, ADR 0019)에서 이뤄졌다. 결론은 **Infisical 재도입이 아니라 "로컬 `.env` 수동 관리" 쪽으로 정식 확정**이다 — 프로덕션 비밀값도 Infisical을 거치지 않고 VM 로컬 파일(`~/sunchak/api.env`, `~/sunchak/grafana.env`, git 미포함·권한 600)로 직접 관리되고 있다(`docs/STATUS.md` "VM의 비밀값 파일" 절). Infisical CLI는 이 프로젝트 생애주기 동안 실질적으로 한 번도 프로덕션 운영에 쓰이지 않았다. 남은 실질 위험(2026-08-08 개정 이력이 언급한 "유출 위험·기기 간 수동 동기화 실수")은 여전히 감수 상태로 남아있고, 완화책은 파일 권한(600)·git 제외뿐이다 — 향후 규모가 커지면 재검토 대상.
